# Concurrent directory access

`IOClientBase.RootDirectory` publishes one root under a private lock. Concurrent first access shares this identity, so child creation/deletion invalidates the same parent cache. `ResetDirectoryCache` shares the publication lock and starts a fresh root for subsequent callers; previously returned objects remain usable.

Synchronous `DirectoryInfo.GetDirectories` and `GetFiles` use their existing native asynchronous counterparts. Sync/async callers share one listing gate, a successful snapshot and parent references. A failed lookup is not cached. Cache reset during a pending request prevents publication of that stale snapshot. The recursive synchronous listing uses its local result without writing it back after a reset.

Synchronous create/delete/rename/move operations delegate to their existing native implementations, preserving their default directory kinds and identity behavior. They invalidate affected caches even after uncertain failure, without replay. Other existing mutation invalidation sites use generation-aware reset methods so a pending listing cannot republish stale contents. Existing public/protected signatures and interfaces remain intact.

Concurrent individual listings are supported. This does not make a multi-step create/check/upload/delete workflow atomic. Callers must coordinate conflicting operations on the same resources. Provider rules still apply: one document can have references in different collections but only one folder location within a particular collection. Reset old-location caches when changing those references through another directory object. Shared integration accounts remain exclusive across jobs/chats/CI.

Isolated regressions control pending native lookups and cover sync/async waiters, simultaneous sync callers, reset/failure behavior and root publication. An actual private loopback server reproduces two HTTP requests before the fix and one shared request afterward. The separate explicit `AddFileLinksWithSpecialCenterDeviceBehaviour_Parallelized` bridge regression replaces the old ignored fixed-path test. It waits for each setup level, journals two unique owned collection names and child paths before creation, checks source/reference/payload identity, removes empty children concurrently and verifies the shared current listing. Cleanup validates both private scopes before deleting the shared owned document, removes children before both collections, checks the root cache and server listings, and verifies exact active/trash absence. It requires the same coordinated exclusive window as the other explicit integration fixtures.
