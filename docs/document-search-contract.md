# Complete additive document search and metadata pages

SearchDocumentDetails and its native asynchronous form implement API 2.29 section 5.2.22 with copied typed query/filter/folder/range/named/field/sort/facet parameters. Original nested named params are objects; the old DocumentSearchNamed.Params string and all legacy APIs/interfaces remain unchanged. Query/filter/named sections, negations, metadata OR units/null matching, original date and decimal strings, duplicate arrays and future fields remain intact. No local normalization, resource lookup or AND/OR rewriting occurs. Tags/collections/folders use the manufacturer's AND behavior; other listed exact arrays use OR. The server remains responsible for field/catalog validity, named-query combinations and role-dependent public inclusion.

Known JSON structures, nonnegative offset/search rows, positive facet size, Int64 size bounds, exclusive includes/excludes and required known named/sort parameters are validated before authorization. Typed numeric convenience properties use Int64; complete raw parameters preserve wider pagination integers. Dates retain original ISO strings without conversion, and range ordering is not computed locally. Explicit false/zero/empty choices remain distinct from omission. No default text/sort/paging choice is inserted, and no limit is silently clamped or offset reset. The reference specifies server text truncation, at most 500 rows and search offsets up to 5000; actual server limits and errors remain authoritative.

GetDocumentPage implements section 5.2.21 with explicit identifier/location/last-change/public/field/paging queries. Its latest-version metadata is ordered by descending version date; lower/upper last-change bounds are inclusive/exclusive, unlike the inclusive search-date upper bounds. Metadata page rows must be positive, while search supports zero. Both interfaces return immutable metadata, original total-hit integers and exact RawJson. Parsed fractional numbers use Json.NET's bounded default precision; exact spelling remains available in RawJson. Search score/workflows and future fields remain accessible in each document's raw details.

Search can omit documents for an empty or out-of-range page; metadata GET requires its documents array. Omitted metadata remains unknown, and explicit ID exclusion allows unidentified projections. Hidden owners/sharings do not imply permissions. The reference describes facets as an array but gives keyed-object examples; both original structures are retained without normalization. Invalid known responses, duplicate/trailing JSON and invalid identities retain inner diagnostics. Native cancellation reaches authorization and HTTP I/O; original server errors remain intact.

Search has indexing delay and only indexes the latest version. Direct metadata reads are current. The manufacturer has no document-search cursor/scroll endpoint; these APIs expose one explicit page and preserve existing helpers. They do not promise stable snapshots, exhaustive results, automatic pagination or safe traversal under concurrent mutations. Timeline/audit cursor APIs are separate contracts. Server-dependent real query/index/facet/role acceptance, owned cleanup, publication and downstream adoption remain separate in #18/#15.
