# Complete additive link and upload-link contracts

API 2.29 sections 5.6/5.7 already had legacy route entry points but incomplete parameter/model parity. Separate configured methods preserve every existing member, interface, constructor and default. The legacy upload-link create (both forms) and async update tag bodies now send the declared JSON array instead of a JSON-encoded string; three regressions fail before the correction and pass afterward. Casing, duplicates, empty password, explicit false and unrelated omitted choices remain unchanged.

CreateConfiguredDocumentLink/FolderLink/CollectionLink accept copied optional LinkAccessControlOptions: original expiry string, integer download limit, password and nullable view-only/hide-date. No false/date/limit default is inserted. GetLinkDetails returns immutable complete identity, original URLs/targets, nullable original controls/counters and future data. ReplaceAccessControl replaces the complete state; an explicit empty object removes previous optional controls according to server policy. It never reads/merges current controls or changes the target. RemoveLink escapes one selected identity and sends bodyless DELETE. Existing older methods retain their previous behavior.

CreateConfiguredUploadLink supports optional name, exclusive collection/folder target, real tag arrays, original expiry, positive upload count, positive Int64 GiB-aligned byte limit, password and explicit creator notifications. Omission retains server defaults without hardcoding one week, 50 uploads or 2 GiB. UpdateConfiguredUploadLink is partial: omitted fields retain current values, and an explicit new target replaces the previous target type. Empty/raw-null password remains explicit for removing protection; typed null setters omit choices. No target/creator lookup, metadata merge, inferred clear, unit conversion or limit clamping occurs. Future raw fields survive. Typed numeric convenience inputs use Int64; raw download/upload-count integer choices retain wider values for server validation except the explicitly long max-bytes contract.

GetUploadLinkDetails on selected/plural clients returns immutable complete creator/name/dates/targets/tags/limits/usage/notification/password metadata and original server web URLs. No URL is reconstructed from the configured legacy upload-link origin, and no creator or zero count is inferred. Complete selected/create RawJson is exact; embedded list entries have null individual RawJson, while the list retains the exact whole envelope. Original arbitrary-width metadata counters remain integer text; parsed future fractions use Json.NET's bounded precision. Missing arrays, duplicate list identities, malformed known structures, duplicate/trailing JSON and mismatched selected identities retain inner diagnostics. Equivalent UUID spellings correlate without changing original selected wire IDs.

The server enforces visible-resource roles, external ownership, creator-only upload-link management, one link per selected resource and mandatory control/password criteria (including error 322). Expiry/download limits can invalidate normal links; upload limits can disable an upload link and explicit limit updates can re-enable it. A target becoming inaccessible can leave an upload link valid while placement stops; the SDK does not infer continued placement or permissions. Public REST management does not grant privileged access to linked resources. Returned passwords must not be logged, and URLs are never distributed, navigated or fetched implicitly. Native cancellation reaches authorization and HTTP I/O; uncertain creations/updates are not replayed. Actual creator/guest/policy/lifecycle acceptance, owned cleanup, current matrix, publication and DMS consumption remain separate in #82/#15.
