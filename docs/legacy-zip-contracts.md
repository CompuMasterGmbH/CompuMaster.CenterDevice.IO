# Deprecated selected GET ZIP endpoints

API2.29 sections5.2.17/18 use bodyless GET `/documents?ids=<comma-delimited-ids>` with `Accept: */*` for original current files or `Accept: application/pdf` for existing PDF representations. The response is a ZIP. Additive explicitly obsolete `DownloadDocumentsAsZipLegacy` sync/native-async forms cover both historical routes; the modern POST `DownloadDocumentsAsZip` remains the recommended normal workflow and is unchanged.

Selections are nonempty, copied exactly once before authorization, and preserve spelling/order/duplicates. Commas inside individual IDs are rejected before authorization because the old comma-separated protocol cannot distinguish them from additional selected IDs. The complete selector is query-escaped; no document ID can inject another query or fragment. Bridge base directories/API prefixes are preserved. Only original and PDF representations are accepted; no conversion is requested and the server includes only visible current documents. URI-length and already-existing-PDF limitations remain documented; success does not establish complete visibility.

The existing unbuffered response-owned streaming path retains authorization/admission/native cancellation/error handling and disposal. Callers dispose the returned stream. Responses, wrappers and error bodies are disposed on failures/cancellation. No body, redirect following or new read replay is introduced. Existing modern methods/interfaces/defaults remain unchanged.

Twenty-four isolated cases cover both representations/forms/base separators, exact selected GET/query/header/body behavior, copied selections, delimiter rejection, pre/active cancellation, lazy response ownership/disposal and HTTP failures. Three real public-factory TCP probes verify actual headers/query/native streams and no new reconnection. Actual server ZIP/ready-PDF/role acceptance remains separately coordinated in #88/#15/CompuMaster.Dms#90; source presence is not complete request-model/permission or publication evidence.
