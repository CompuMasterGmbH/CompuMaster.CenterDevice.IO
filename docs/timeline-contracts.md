# Complete timeline search and scroll

API2.29 sections5.15.1–3 are covered by additive `Timeline.SearchTimeline` and `Timeline.ScrollTimeline`, with synchronous and native asynchronous forms. Historical methods/interfaces, timestamp conversions, MaxRows and default rows remain unchanged.

Requests are copied before authorization. Original types, creator user IDs and document IDs preserve order/spelling/duplicates and explicit empty arrays; distinct limits are50/10/100. UUID filter identities count canonically without rewriting them. Search accepts original inclusive from/exclusive to ISO8601 strings and optional nonnegative offset up to5000. Scroll accepts an exclusive previous-id and asc/desc; null sort retains the ascending server default. Missing choices are omitted. A positive requested rows value is never clamped; the server currently returns at most1000. Search timestamp order and scroll logical event order are distinct. No timestamp filter or offset is silently added to scroll.

Immutable pages preserve server order, original timestamp text (including precision/offset), creator, future event types, full details, future metadata and exact raw JSON. Hidden/omitted optional metadata stays unknown rather than becoming an authentication-context value. Event/page objects are defensive copies. Invalid types, missing event identities, duplicate canonical identities, exclusive-cursor repeats, oversized pages, duplicate properties and trailing JSON retain inner parse diagnostics. Unknown event detail keys and wide integer values are not discarded or narrowed. This preserves the complete section5.15.3 event catalogue without a closed enum that would reject future types.

Visibility is determined at event creation time; document-ID filters exclude unrelated event types. Empty results do not establish permissions or current resource visibility. Unknown/expired cursor errors remain server errors; callers decide explicit resource reconciliation. No automatic page fetch, cursor advancement, hidden synchronization reset, local sort or new retry is introduced. Native cancellation reaches authorization/admission/HTTP I/O. Existing configured authorization/error handling remains in force.

Fifty-six new isolated cases include three actual public-factory loopback probes and cover options/defaults/limits/duplicates, copied mutable inputs, original complete metadata, malformed pages/cursors, cancellation, unchanged legacy wire behavior and original HTTP failures. Real Teamwork event/role/filter/cursor acceptance, direct manufacturer login, current serialized matrix, publication and exact downstream adoption remain separate #86/#15/CompuMaster.Dms#90 criteria.
