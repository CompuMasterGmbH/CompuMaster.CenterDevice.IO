# Explicit collection creation and update

CreateConfiguredCollection and UpdateConfiguration add synchronous/native asynchronous coverage for API 2.29 sections 5.3.1–5.3.2 alongside unchanged name-only creation/rename methods and interfaces. The required creation name and all explicit unique/public/disclosure/auditing/archive/duplicate-check choices retain their original values; omission inserts no defaults. Document/user/group arrays preserve order and duplicate identities. Extended metadata preserves original strings/string arrays. Complete intelligent filters retain nested named parameters, folder filters, original date strings and future fields without resolving identities or calculating dates.

CollectionCreationRequest and CollectionUpdateRequest copy source objects and nested selections. Typed null setters omit properties; invalid known JSON kinds fail before authorization. Intelligent creation must omit documents and public, even explicit false. Server ownership, role, module, uniqueness and normal/intelligent restrictions remain authoritative. Auditing is irreversible; test archives require established cleanup/unarchiving capability before creation. No automatic action, grant, additional lookup or new speculative mutation replay occurs.

HTTP 201 confirms creation even when failed-documents, failed-users or failed-groups are returned. The result retains those original failures; callers must inspect them rather than infer atomicity or complete sharing. A usable created identifier is required. Malformed success retains its inner diagnostic. Duplicate-name HTTP 409 remains an original server failure. HTTP 204 confirms a property update. Cancellation reaches authorization and HTTP I/O but cannot establish that a write did not happen.

Isolated fixtures validate all explicit choices, nested original filters, snapshots, partial responses, malformed known structures, errors and cancellation. They do not create actual collections, shares, audits or archives. Real role/module/state acceptance, cleanup, publication and downstream adoption remain separate in #19/#15.
