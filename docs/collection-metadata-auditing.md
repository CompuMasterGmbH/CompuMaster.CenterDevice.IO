# Collection custom metadata and auditing

Additive concrete-client sync/native asynchronous commands cover API 2.29 sections 5.3.7–5.3.13, retaining existing APIs/interfaces/defaults. All requests select an escaped collection ID and use the original POST action, with HTTP 204 confirmation. Parameters are copied before authorization; no speculative replay, state lookup, permission repair or extra sharing request is added.

Custom metadata uses explicit `set` string/string-array values and `unset` names. Both may be supplied together; unspecified keys remain unchanged, existing values are replaced regardless of their former scalar/array type and missing unset keys are ignored by the server. Original empty values, arrays, order and names remain intact. The client does not guess precedence for overlapping selections. Known shapes are validated; typed null omits a parameter and unknown future JSON remains copied.

Auditing requires collection ownership, a non-public collection without shared folders and tenant feature/role availability. Enabling it cannot be undone; owner email settings start disabled. Opt-in applies only to an audited collection shared with the caller and cannot be undone by opt-out or reset. Opt-out applies before opting in. Only the owner can reset opted-out users; opted-in states cannot be reset. The client never infers those states from caller roles.

Explicit resend selects original pending-user IDs and causes another email per invocation to those users who have not responded. It is never called automatically, repeated on partial state guesses or exercised against actual recipients by isolated tests. Owner email settings preserve explicit opted-in/out booleans and original pending-response period strings, with documented monthly/weekly/none catalogs left for server validation. Omitted values remain omitted and no notification defaults are inserted.

Native cancellation reaches authorization/admission/I/O but cannot establish that no metadata, audit consent or email changed. Non-204 statuses remain original failures. Isolated fixtures/private TCP tests verify exact actions, parameter absence versus explicit shapes, snapshots, errors and cancellation; they do not establish actual audit/module/role/notification acceptance. Exact-owned coordinated server acceptance and verified cleanup remain separate #19/#15 criteria, as do publication and downstream adoption.
