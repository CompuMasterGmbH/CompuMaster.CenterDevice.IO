# Selected and bulk document removal

API 2.29 sections 5.2.6–5.2.9 distinguish reversible trash movement from direct permanent erasure. The additive `Document.MoveDocumentToTrash`/`EraseDocument` and `Documents.MoveDocumentsToTrash`/`EraseDocuments` methods have synchronous and native asynchronous forms. Existing `DeleteDocument`/`DeleteDocuments`, interfaces and defaults remain unchanged.

Selected trash movement sends bodyless DELETE to the escaped document resource. Selected direct erasure sends POST with only `action: erase`. Bulk operations send `action: delete` or `action: erase` and the explicit document array, preserving original order, spelling and duplicates. The nonempty selection is enumerated once and copied before authorization. Bulk `includeErrorInfo` is nullable: null omits the query, false requests identifier failures and true requests detailed failures. No tenant default or role is guessed.

HTTP 204 reports complete success with empty immutable failures and null raw JSON. HTTP 200 must contain nonempty failures correlated to the explicit selection; a selected response must identify exactly one failure. Identifier-only failures retain unknown error code/message/data as null. Detailed failures retain original integer-code text without narrowing, original message, defensively copied data and complete future fields. The exact response JSON remains available. Duplicate/trailing JSON, wrong shapes, missing identities and foreign IDs fail with the original parse diagnostic as an inner exception. Canonical UUID spellings correlate without rewriting the returned IDs.

The server controls ownership, roles and the document-deletion tenant setting. Permanent erasure cannot be undone. Side effects can be idempotent while subsequent failure lists differ; no uncertain write or reported failure is automatically retried. Cancellation reaches authorization/admission/native HTTP I/O and does not establish that a submitted removal had no effect. The selected and bulk document endpoints are distinct from trash endpoint erasure and do not clear an account or tenant.

Seventy isolated cases cover all wire/default/status choices, malformed failures, copied selection, original wide error metadata, cancellation and original HTTP errors, including six real loopback TCP probes through the public factory. They do not establish actual Teamwork roles, ownership or erasure behavior.
