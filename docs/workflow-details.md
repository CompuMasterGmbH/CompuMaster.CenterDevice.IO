# Selected workflow details

API 2.29 section 5.20.6 is available through `Workflows.GetWorkflowDetails` and its native asynchronous counterpart. A bodyless GET selects an exact workflow identity. Nullable include-document-visibility preserves omission versus explicit false/true: false or omission considers participant visibility; true also considers document visibility. The server determines actual visibility, and no local access grant is inferred.

`WorkflowDetails` is immutable and retains original workflow/document identity, positive Int64 document version, creator ID, type/status/overall result, confirmation mode, visibility, comment and exact ISO8601 date text. Optional fields remain null without inventing caller identity, completion, document access or defaults. Date strings preserve original precision/offsets and never acquire a workstation timezone. Metadata-form and future types remain original despite the detail section's illustrative type list mentioning only read/approval.

Participant fields are role-dependent. Missing/JSON-null users, groups, assignees, not-responded users, all responses, caller response and attachments remain unknown; explicit empty arrays/objects remain empty. In particular, omitted assignees do not authorize an assumption of unassigned state, and hidden responses do not mean that nobody responded. Group selections are not synthesized into resolved participant counts. Complete copied response objects preserve original user/version/result/date/comment and future fields; caller response receives no fabricated user ID. Attachment pairs retain exact document identity and explicit version, rather than filenames or latest-version sentinels.

Completion data preserves original field keys/default strings and future nested data without evaluating current document metadata. Creator-visible finalizing data stays null when hidden; it must not be rewritten as an invented empty action definition. Complete future result/action names and data remain defensive copies. Reading and constructing details execute no actions, notifications or sharings. The complete original role-dependent JSON envelope remains available through a defensive Data copy, including future attachment/response fields.

Selected identity is compared canonically for GUIDs while retaining the server's original ID. Malformed JSON, trailing envelopes, mismatched identity and wrong known scalar/array/object/version shapes fail with original inner causes. Known optional fields are validated when supplied; the client does not fabricate absent universal or role-dependent metadata. Original permission/transport diagnostics and unexpected statuses remain errors instead of fake empty detail. Native cancellation reaches authorization, admission and HTTP I/O; safe bounded GET retries follow existing transport defaults. Existing command interfaces/defaults are unchanged; changing the concrete class to partial only organizes additive source.

Isolated fixtures cover sync/native calls, visibility omission/false/true, unknown-versus-empty role projections, original creator, document/attachment versions, raw dates/metadata defaults, future types/nested data, immutable lists/copies, canonical identity, schema/Int64/envelope failures, original errors and cancellation. Four actual public-factory loopback HTTP probes verify bodyless prefixed GET, UTF-8, visibility query and existing bounded retry. Actual participant/document visibility, creator-only fields, group resolution and role grants require coordinated exact-owned Teamwork acceptance and cleanup. Direct workflow creation, filtered listing, full post-merge matrix, explicitly approved publication and downstream adoption remain separate.
