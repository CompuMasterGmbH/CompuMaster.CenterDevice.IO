# Collection audit logs

`client.AuditLog.Search[Async](contextId, collectionId, request)` implements API 2.29 section 5.18.1. Search returns decreasing timestamp order with offset 0–5000 and positive optional rows (the server caps returned pages at 1000). Omitted options retain server defaults; explicit empty lists remain explicit. The client snapshots nested options before authorization. Filters allow 20 distinct type names, 10 users and 10 document IDs, unlike the separate legacy timeline contract. Timestamp lower bounds are inclusive and upper bounds exclusive.

`Scroll[Async]` implements section 5.18.2 and requires an audited collection. It retains logical server event order, which need not match timestamp order. Omit `PreviousId` to start; pass the last returned event ID unchanged to retrieve the next page. The previous event is excluded. Select an explicit `Rows` value and stop when the page contains fewer entries. An unknown cursor remains a server error; no fallback, automatic iteration, total or next-page flag is inferred. These reads never enable auditing or freeze a collection.

Events preserve unknown future string type names, optional creator, exact timestamp text and defensive raw details. Timestamps with an explicit offset expose `DateTimeOffset`; offset-free text does not acquire the workstation timezone. Missing metadata stays unknown. View/download events (`document-viewed`, `document-downloaded`, section 5.18.3) expose optional typed document ID, accessed version and historical filename. Their visibility requires auditing and collection ownership; an empty result does not establish auditing, role permission or absence of activity.

Both synchronous and native asynchronous methods preserve context, cancellation, existing expired-token refresh and original failure causes. Uncertain POST outcomes are not replayed. The legacy timeline client, public interfaces and default behavior remain unchanged.

Isolated contract tests cover the distinct filter limits, nested snapshot, inclusive/exclusive bounds, cursor identity/order, unknown metadata, 64-bit values, malformed successful pages, errors and cancellation. Actual audited-collection scrolling, owner-only access events and other-role visibility require separate server acceptance; source coverage alone does not establish these capabilities through Teamwork or direct manufacturer login. Publication and default DMS package adoption remain separate prerequisites.
